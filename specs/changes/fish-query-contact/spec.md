# 个人消息查鱼助手

Status: done

## Problem Statement

玩家需要在游戏内查询目标鱼种的推荐鱼饵与钓法，而不必离开游戏打开网页。

## Solution

在固定联系人“查鱼助手”的个人消息入口接入只读查询。发送“鱼名 [地图]”，查询当前地图或指定地图，返回当前时段最多三条方案；不提供鱼获档位筛选。

## User Stories

1. 玩家直接发送鱼名或“帮助”，无需输入 `/gm`。
2. 回复只送达请求者并保存在收件箱；普通玩家之间的消息不执行查询。
3. 未识别鱼名、地图无此鱼或没有可行方案时明确提示；拼音前缀规则见 `specs/changes/fish-query-pinyin/spec.md`。
4. 回复区分攻略参考点和已参与计算的世界落点，不将历史参考坐标当成概率最优位置。

## Implementation Decisions

- 在随机取鱼前读取现有权重，复用饵效、天气、鱼群、技能与体重模型的确定性参数；查询不发鱼、不耗饵、不修改玩家数据或抽取生产随机数。
- 仅查询一张地图、当前时段、单饵无窝料；天然饵和拟饵各最多24组。按含空口及咬饵接受率的单次判鱼估计概率排序，不声称官服概率或全局最优。
- 入口只接受鱼名及可选地图，包含目标鱼全部档位；回复标题只显示地图和完整鱼名。完整鱼名/编号优先，其他按无声调拼音前缀取固定排序首种。
- 攻略参考点不参与概率计算。海图沿用最多六个有依据的落点并假设已上船；内陆暂不扫描区域，未指定世界坐标时按场景默认位置项估算。
- 装备限重关闭时使用永久技能；开启时需先拿起鱼竿，使用该竿的限重、技能和可用钓组。
- 保留3秒计算预算，名称解析及计算超时使用同一提示；每次只发送最终回复，不承诺客户端端到端延迟。
- 客户端基线为 `4.0.25034`：`24/4` 为普通 u32 数组，`24/19` 为 bytes 包装的 `dgbmlekfpbg`/2002，个人消息沿用 `19/1` null 应答、`19/10` 推送及现有邮件读取；协议依据见 `docs/debugging-workflow.md`。
- 回复写入既有邮件表并沿用事务及请求回执，不改公共聊天、表结构、管理权限或客户端文件；助手不接收物品。
- 回滚只需更换程序，无存档转换；已经保存的文本回复仍保留。

## Testing Decisions

- 手算候选权重与直接概率、与实际抽样对照；查询不消费生产随机数。
- SQLite 覆盖只读查询、指定地图、候选上限、空结果、取消和攻略坐标来源。
- 回复测试覆盖精简标题、鱼种全部档位、帮助/超时、世界落点与参考点分离；拼音测试覆盖同音字、首匹配、完整名优先、BOM和非法输入。
- 协议回环覆盖联系人、资料卡、先应答后推送、隔离、重放和拒收物品。
- 执行完整 `go test ./...`、`go vet ./...`、`go build ./...`；自动测试不替代实机验收。

## Out of Scope

内陆区域网格和地图显示边界、GM 管理、装备保护、鱼口倍率、全天全地图搜索、客户端文件修改。
