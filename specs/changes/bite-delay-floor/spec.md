# 落水保护跟随咬钩倍率

Status: done

## Problem Statement

把咬钩延迟调快（后台参数 `bite_delay_scale` 小于 1）之后，玩家实际等待的时间并不跟着变短：
抛竿后总是要等 6 秒左右才出鱼。倍率只作用在排口延迟上，落水保护仍是固定的 6 秒基础值，
第一轮到点后又被"落水未满 6 秒"顺延回去，玩家感受到的就是固定延迟。

## Solution

落水保护时长改为跟随 `bite_delay_scale`：倍率调快，出鱼间隔同比缩短；倍率极小时也不早于 0.8 秒。
路亚族保持固定 1.2 秒（拟饵落水即生效，没有浮标立稳这一步）。

## User Stories

1. 作为玩家，我把咬钩倍率调快后，抛竿到出鱼的时间应同比缩短，而不是恒定 6 秒。
2. 边界：倍率调到很小时，落水保护不应短于 0.8 秒，避免"落水即咬钩"。
3. 边界：路亚钓组的行为不受倍率影响，仍是 1.2 秒。

## Implementation Decisions

- 模块：`internal/gameserver`（判鱼定时器链路）。把落水保护时长抽成独立函数，`onBiteTimerTicket` 调用它。
- 接口：无协议改动，不新增命令与字段。
- 数据与迁移：无表结构改动、无迁移、无旧库升级。
- 兼容：客户端基线 4.0.25034；旧档兼容；回滚方式为把该函数恢复成固定 6 秒 / 路亚 1.2 秒。
- 参数：读取后台 tunable `bite_delay_scale`，未配置时按 1.0 处理（等价于原行为）。

## Testing Decisions

- 测哪一层：单元（纯逻辑，无 DB、无网络）。
- 期望值来源：常量算例——`6s × 0.25 = 1.5s`、`6s × 0.01 → 800ms 下限`、路亚固定 `1.2s`。
- 覆盖的用例：默认倍率、0.25、0.5、极小倍率下限、路亚、倍率为 0。
- 回滚后哪些测试会变红：把函数改回固定 6 秒后，`TestBiteFloorDelayFollowsScale` 的前三条会失败。

## Out of Scope

- 不改判鱼概率、重量分布与档位线。
- 不改就位守门（`14/7` 动画位）相关逻辑。
- 不改路亚的咬钩节奏与收线窗口。
